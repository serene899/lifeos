# 人生K线图 · 项目现状报告 v0.4.3（联系方式固定顺序 + 顶部按钮吸顶）

日期：2026-11-26 · 版本：0.4.3 · 线上：https://serene899.github.io/lifeos/
仓库：serene899/lifeos（main + gh-pages）

## 1. 本版内容（所有者真机反馈两条）
①两位朋友联系方式相同几项、但显示顺序不一样（添加顺序不同所致），要求像苹果通讯录一样位置定死、呈现顺序永远一致。
②人物详情页顶部的「返回 ‹」和「编辑」按钮会随页面滚走，想返回还得滑回去——要求按钮图层优先级最高、始终可达。

## 2. 联系方式固定顺序
- 新增固定顺序表：手机 → 电话 → 微信 → QQ → 邮箱 → 抖音 → 小红书 → Instagram → WhatsApp → X → 微博 → 单位 → 住址；表外的自定义名称排在后面、保持原相对顺序，同名保持原序（稳定排序）。
- `personContacts()` 返回前统一排序：详情展示、编辑页打开、Markdown 备份导出都走同一顺序；编辑页里增删条目后也立即归位。数据本身仍按原样存，只统一呈现，不改用户数据。
- 附带修复：旧逻辑把「内容是纯数字」也当作电话号码，导致纯数字的抖音号后面出现「拨打 ›」（所有者截图里正有此现象）。现改为只有名称是手机/电话的条目才给拨打；邮箱仍按名称或邮箱形状给「写邮件」。

## 3. 顶部按钮吸顶
- 新增 `.sticky-head`：`position: sticky` 吸在安全区顶部、高图层（z-30）、半透明背景 + 背景模糊，内容从其下方滚过时按钮始终可见可点。
- 应用范围：人物详情（‹ / 编辑）、人物列表（标题 / ＋）、人物编辑页（✕ / ✓）、记录页与数据页的「‹ 返回首页」。均为纯样式与结构调整，不动数据与逻辑。

## 4. 测试结果（桌面 Chromium 模拟 iPhone 13）
- 单元测试 **67/67**（新增固定排序组：两种添加顺序结果一致、自定义名称靠后保序、存量条目同样排序；旧折算用例的期望顺序按新口径更新）。
- 端到端 **5/5**（通讯录用例改为故意先加纯数字抖音号、后加手机：断言详情顺序为手机在抖音前、全页只有一处「拨打」、顶部栏 computed position 为 sticky）。
- 截图核验：详情页向下滚动后 ‹ 与「编辑」仍钉在顶部（内容在其下模糊滚过），联系方式为手机/微信/抖音序、抖音无拨打。

## 5. 待所有者真机验收
①打开两位朋友的详情页，联系方式顺序应完全一致（手机在前）；②在详情页往下滑动，顶部返回和编辑应一直钉在上面、随时能点。

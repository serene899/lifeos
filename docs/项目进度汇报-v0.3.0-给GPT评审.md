## 一、项目定位与不可动摇的原则

LIFEOS 是一套个人人生数据系统，四个 App 全部只存本机（IndexedDB）、无服务器、无账号：
人生K线图（核心）+ 钱在哪（资产）+ 生息（健康）+ 阅迹（阅读观影）。
人生K线图的定位经所有者 2026-11-19 亲自修正为两个核心功能：
①**接收另外三个 App 的内容，汇成 K线图**（主功能）；②**手动记录**（次要，补没有来源的部分）。

硬规则（所有者终审 V0.3.3 + 后续拍板，改动须经他批准）：
1. 六维恰好六个：财务、工作、健康、学习、情绪、精神生活；不算六维平均/总分。
2. 日K 的 OHLC：晨间主观=开、今晚整体=收、当天最好=高、当天最差=低；四值不全只画点、不画蜡烛；缺失留空不当 0。
3. 正式事实只有四项：sleepMinutes、studyMinutes、workMinutes、spendAmount。
4. 事件与人物只作时间轴/故事标记，不增加评分维度。
5. **自动打分（所有者 2026-11-19 拍板，推翻旧口径）**：健康、财务、学习、精神生活四维由汇入的事实自动出分；工作、情绪无数据来源、由他偶尔手点；手动分可覆盖自动分、以手动为准。锚点为试行版，用满 21 天后复核。
6. 三个来源 App 的导出只送事实、不送分（lifeos-exchange v0.1.2）；本 App 的备份格式为 lifeos-export-v1（JSON + 人可读 Markdown 双份，带 SHA-256 校验和）。
7. 所有者的产品教训：首屏必须先给最简路径，完整结构收进折叠区（v0.1.0 曾因「打开看了半天不会用」返工）。

## 三、当前功能与实际逻辑口径（请重点审这一节）

**总览页**：今日状态卡（有手动分显示手动分；没有则显示最近自动分并标注依据）；「已自动收到今天的数据」汇入摘要；六维最近状态；上手说明卡。

**记录页**：日期切换；快速模式每维一个 1–5 点选（今晚整体）+ 今日故事一句话；「记更细」展开后有晨/最好/最差、四项事实、最好/最差时刻原文；约束校验（最好/最差必须包住晨/晚，否则拦下不保存）；有汇入数据的日期显示事实提示行。

**K线页**：六维切换 × 日K（近30天）/周K（近12周）/月K（近6月）。手动数据画蜡烛（四值全）或蓝圆点（部分值）；自动分只出现在日K、画橙色菱形并附依据文字；周/月不并自动分。列表逐日列出数值或「自动分 X · 依据」。

**时间轴页**：事件（可增删改）+ 有故事的日记条目按日期倒序；事件与人物提及只作标记；@ 人名蓝色高亮。

**人物页（v0.3.0 新增，底部第六个 Tab）**：
- 通讯录：名字 + 关系 + 备注。关系是**自由文本**（有朋友/同事/同学/家人/亲戚/店里客人/网友快捷片，但可任意自填），因为所有者明确说生活关系太多、不可枚举；关系可留空后补。
- 记录页故事框输入 @ → 弹出选人条（按字过滤、显示关系），点选插入纯文本「@名字」；没有此人可当场新建（关系后补）。
- 人物详情：与此人有关的天数/提及数 + 全部相关日子（故事/最好时刻/最差时刻/事件四来源，倒序，点跳那天记录）。
- 提及解析：按通讯录现有人名做最长匹配（@王子怡 不会被拆成 @王子）；纯文本存储，导出可读。已知取舍：改名后旧提及不再匹配（详情页有提示）。

**数据页**：置顶「收数据」（选交换文件→预览来源/条数/天数→收下；汇入层与手动数据分开存，可整层清除）；历史记录列表（点跳记录页）；导出 JSON/Markdown；导入（校验格式、维度白名单、事实白名单、校验和，预览后合并或覆盖，覆盖前自动备份当前数据）；载入/清除示例数据；清空全部。

**自动打分试行锚点**（图上标注「自动分·试行」与依据）：
- 健康：睡眠时长 ≥8h=5、≥7h=4、≥6h=3、≥5h=2、<5h=1；有睡眠质量自评时与时长分取平均。
- 财务：当日总资产（CNY 快照）较昨日涨跌幅 ≥+1%=5、≥+0.2%=4、±0.2%内=3、>-1%=2、≤-1%=1；只有支出不出分（支出多≠财务差）；需至少两天快照。
- 学习：学习/阅读时长 ≥90min=5、≥60=4、≥30=3、≥10=2、>0=1。
- 精神生活：当天有读完/看完=5、写了感受或摘句=4、只有记录=3。

**数据汇入解析口径**：sleepMinutes/studyMinutes 同日多条取最新（不累加）；spendAmount、收入、运动分钟、餐次、阅读分钟按日累加；资产快照只认 CNY；op=void 在文件内抵消同 id 的 write；未知指标跳过并计数。

## 四、已知问题与取舍（Atlas 自查）

1. **真机未验收**：全部版本只在桌面模拟器测过，iOS Safari/PWA 的真实表现（尤其主屏幕打开、存储持久性）未经所有者真机确认。
2. **「实时共享」只做了一半**：目前是文件接力（来源 App 导出文件 → 本 App 导入），不是打开即自动同步。未做同源直读的原因：三个 App 数据库结构各异且随版本变化，读错会污染图；iOS 主屏幕 PWA 存储是否互通未真机验证。
3. 图标 PNG 无法经当前通道推送 GitHub（连接器二进制限制，四个 App 通病），主屏幕图标可能显示回退样式，功能不受影响。
4. 最好/最差时刻输入框没有 @ 选人条（手打 @名字 仍可识别高亮），只给故事框接了。
5. 人物改名后旧提及失联（纯文本方案取舍，见三）。
6. 周/月 K 线不含自动分，长期只靠汇入数据的人，周/月视图会大面积留空——这是口径决定，但与所有者「主要靠自动汇入」的用法可能冲突，值得评审。
7. 自动分锚点未经真实数据检验（所有者实际汇入次数还很少），21 天复核机制已约定但未到期。

# 人生K线图 · 项目现状报告 v0.4.0（双入口改版 + Apple 风格 UI）

日期：2026-11-21 · 版本：0.4.0 · 线上：https://serene899.github.io/lifeos/
仓库：serene899/lifeos（main + gh-pages）

本版按所有者《v0.4.0 产品改版指令》执行：结构精简为两个一级入口 + Apple 风格 UI 系统优化；随后按所有者提供的苹果通讯录截图，再把人物三页（列表/详情/编辑）按苹果通讯录的分组列表样式重排。数据引擎、评分规则、交换/备份格式未动。

## 1. 修改了哪些页面
- **新增 Home（首页）**：合并原总览、K线、时间轴三页职责（见下）。
- **删除**：Overview（总览）、Kline（独立K线页）、Timeline（时间轴页）三个屏幕组件（功能已归并，数据未删）。
- **Record（记录）**：改为二级页——顶部「‹ 返回首页」，保存/删除后自动回首页；功能与校验零改动。
- **Data（数据）**：改为二级页「设置 · 数据」，从首页右上角设置入口进入，顶部带返回；内容零改动。
- **People（人物）**：列表/详情/编辑三态全部按苹果通讯录样式重排（见第 6 节）。

## 2. 原来的六个 Tab 如何处理
| 原入口 | 新位置 |
|---|---|
| 总览 | 不再独立存在；首页打开即 K 线图（今日状态卡、上手说明卡、汇入摘要卡、六维状态卡全部撤下） |
| 记录 | 首页「记录今天」按钮 → 二级页；日期详情里也可进任意一天 |
| K线 | 成为首页核心内容 |
| 时间轴 | 融入首页：点任意一天打开「日期详情」，看当天的故事、最好/最差时刻、手记事实、自动汇入与自动分依据、事件（可增删改） |
| 数据 | 首页右上角「⚙ 设置」→ 二级页 |
| 人物 | 保留为第二个一级入口 |

## 3. 新的两个导航如何实现
底部导航只剩「首页 / 人物」两项（grid 两列，选中蓝色）。记录页与设置页是覆盖式二级页（打开时底部导航隐藏，靠页面内返回按钮回首页），不占一级入口。

## 4. 首页 K 线图的最终布局
从上到下：标题「人生K线图」+ 右上设置入口 → 六维分段控件（iOS 风格：灰轨道 + 白色选中片）→ 日K/周K/月K 分段控件 → K线图卡片（视觉中心；网格线降至 7% 不抢眼；空数据有专门空状态文案）→ 一行极简图例 → 「✎ 记录今天」主按钮 → 日期/周期列表（点日行展开日期详情）。深色模式同步适配（选中片在深色下为中灰，截图已核）。

## 5. 记录功能如何融入首页
首页主按钮「记录今天」进入；日期详情里「记录 / 编辑」可进任意一天；人物详情的相关日子点按仍可跳到那一天的记录页。保存成功自动回首页并立即看到新蜡烛。快速模式默认、折叠详细区、@ 提及、事实字段、约束校验全部原样保留。

## 6. 人物模块保留了哪些功能
功能全保留：新增/编辑/删除、搜索、关系自由文本 + 快捷片、备注、@ 提及与详情关联（故事/最好/最差时刻/事件四来源）、关联天数与提及次数、联系方式（手机可拨打、邮箱可写信）、生日/纪念日「还有 X 天」、列表生日临近标记。
按苹果通讯录截图重排（本版追加项）：
- **列表**：右上角圆形 ＋ 添加；全部人物收进一张大圆角分组卡逐行排列（名字主信息、关系与备注辅助、右侧天数/生日）。
- **详情**：圆形 ‹ 返回 + 右上「编辑」；名字居中大字、关系与备注作副标题；关联日子、联系方式、重要日子均为分组卡，统一「标签小字在上、值在下」两行式（与苹果联系人详情一致）；删除联系人是底部独立红色行。
- **编辑**：顶部圆形 ✕ / ✓（与苹果一致）；基本信息、联系方式、重要日子都是分组卡内无边框行输入 + 细分隔线。
- 按改版指令 5.4：联系方式/生日等字段**不再扩展**，且在编辑页收进「更多信息」折叠区（已有值自动展开）；姓名、关系、备注、关联故事为第一优先。字段与已存数据全部保留，未删任何数据。

## 7. 原有数据是否完整保留
完整保留。Dexie 仍 v3、表结构零改动，旧数据直接可读；导出 lifeos-export-v1（含可选 people 字段与校验和口径）与 lifeos-exchange 导入均未改动，旧备份可正常恢复（e2e 用旧流程验证：记录→刷新仍在、旧交换文件导入、导出格式断言）。

## 8. 周K、月K 自动评分是否修复
**已修复**。旧口径：周/月只聚合手动 OHLC 字段，自动分完全不进。现在按指令第七节的「有效评分」口径聚合：每天先取有效评分（手动晚间优先的代表值；手动没记才用自动分），周期开=第一条、收=最后一条、高=最高、低=最低；只有一条有效评分时只画点；没有就留空。列表明示「有效评分 X/Y 天（含自动分 Z 天）」。注意口径变化：周/月蜡烛的开/高/低/收从此来自每日有效评分序列，不再来自晨/最好/最差字段的拼接（日K 不受影响，仍是晨/最好/最差/晚四值蜡烛）。自动分锚点本身未改。

## 9. 测试结果（桌面 Chromium 模拟 iPhone 13）
- 单元测试：**53/53 通过**（含新增 3 条周/月纳入自动分的用例：纯自动成蜡烛、手自动混合手动优先、单条自动只给点）。
- 端到端：**5/5 通过**（两入口结构断言、记录→保存回首页→蜡烛→点日看故事、约束拦截、交换文件导入后日K自动点 + 周K含自动分、@ 提及全流程、日期详情加事件 + 导出格式 + 示例数据）。
- 类型检查：tsc 0 错误；生产构建成功。
- 截图核验：首页浅色/深色、周K、人物列表/详情/编辑共 6 张，布局无溢出、分段控件与分组卡在两种模式下均正常。

## 11. 当前仍然存在的问题
- PNG 图标仍无法经 GitHub 连接器推送（老问题），主屏幕图标可能显示回退样式，功能不受影响；需所有者在 GitHub 网页端上传原图。
- 周/月K 新口径下，单日「最好 5、最差 1」的波动不再进入周蜡烛的高低（只认每日有效评分）——这是新口径的定义使然，若想保留极值口径需另行拍板。
- 自动分 21 天试行复核未到期（2026-11-19 起算）；同源直读同步仍未做，继续文件接力。
- 人物详情未做头像/照片（苹果截图有照片墙，本产品无照片字段，按「不擅自增加功能」未加）。

# 人生K线图 · V0.3.3 规格合规说明

本文件记录所有者 2026-11-19 下达的 V0.3.3 终审 12 条规则在本代码中的落点。
仓库接管时的现状：`serene899/lifeos` 只有一个 `# lifeos` 的 README 和一次 Initial commit，
没有任何代码、文档或 Grok 留下的成果（Grok 的 GitHub 设备授权未走通，未推送任何内容）。
因此本项目为在该仓库上的首次实现，不存在覆盖既有成果的问题。

| # | 规则 | 落点 |
|---|---|---|
| 1 | LIFEOS 核心项目 | 本仓库即 LIFEOS 本体 `serene899/lifeos` |
| 2 | 六维度：财务/工作/健康/学习/情绪/精神生活 | `types.ts` 的 `DIM_KEYS` 恰好六个；导入校验拒绝第七维 |
| 3 | 关系与生活事件只作时间轴标记，不加评分维度 | `LifeEvent` 只有 date/title/note，无 dimension、无 score 字段；单测断言 |
| 4 | 日K无真实 OHLC 时不强行生成标准蜡烛 | `kline.ts dayBar`：四值齐全且约束成立才 `candle`；部分值 `point`；无值 `empty`。单测 + e2e 覆盖 |
| 5 | 缺失留空，不当 0、不当状态差 | 所有状态/事实字段均为可选 `undefined`；序列中缺失日为 `empty` 格，不用前值填充。单测覆盖 |
| 6 | Open=晨间主观、Close=晚间主观、High/Low=真实最好/最差 | `DimState.morning/evening/best/worst`，聚合规则见 `aggregateBar` |
| 7 | 六维平均值不能代表人生整体状态 | 全应用不计算、不展示任何六维平均或总分；总览逐维展示；`kline.ts` 无 average/overall 导出（单测断言）；Markdown 导出不含「总分」（单测断言） |
| 8 | 正式事实指标只有 sleepMinutes / studyMinutes / workMinutes / spendAmount | `DayFacts` 类型只有这四项；`FACT_KEYS` 白名单 |
| 9 | 运动分钟、餐食次数、资产快照、模拟盈亏等不得进入正式事实层或评分 | 类型层根本没有这些字段；导入校验对白名单外事实字段（含 exerciseMinutes 等点名字段）拒绝整份文件。单测覆盖 |
| 10 | 评分锚点仍是候选规则，须实际使用 21 天后确认 | UI 与文档均标注「候选锚点」；`ANCHOR_CANDIDATE` 命名带 CANDIDATE；未写成定稿 |
| 11 | 导出格式遵守 lifeos-export-v1 | `exporter.ts`：format=`lifeos-export-v1`，含 counts 与 SHA-256 校验和；导入先校验（格式/条数/校验和/白名单）再预览后写入 |
| 12 | 两个尚待确认的规则继续保持待确认，不得擅自定稿 | 见下方「待确认清单」，本版一律按最保守口径实现，未定稿任何一项 |

## 与早期草案的差异（以 V0.3.3 为准）

本地《LIFEOS-定义冻结草案-v1》（2026-11-10，未冻结）曾定义 Open=前一日收盘值、
并设计了六维加权综合值；两者都与 V0.3.3 冲突（Open 改为晨间主观状态；平均值不得代表整体），
本实现以 V0.3.3 为准，草案的这两点不采用。草案中与 V0.3.3 不冲突的部分
（六维边界、缺失处理、双份导出、覆盖前留底）继续沿用。

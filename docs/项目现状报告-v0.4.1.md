# 人生K线图 · 项目现状报告 v0.4.1（真机反馈修复 + 联系方式自定义 + 人物头像）

日期：2026-11-22 · 版本：0.4.1 · 线上：https://serene899.github.io/lifeos/
仓库：serene899/lifeos（main + gh-pages）

本版来自所有者 v0.4.0 上线当晚的真机反馈，共四件事：@ 提及选不了人、页面被放大切边、联系方式改自定义、人物加头像；另按所有者要求参考阅迹的完成度做了两处 UI 打磨。

## 1. @ 提及选不了人——已修复（根因明确）
所有者反馈：已添加的联系人，在记录里打 @ 却选不了。
根因在输入触发规则：旧规则要求 @ 前面必须是空格或标点才弹出选人条，但中文里最自然的写法是紧贴汉字打「跟@某某」，于是选人条根本不弹（保存后的解析其实认这种写法，只有输入时弹不出）。
修复：
- 触发放宽：@ 前可以是任意字符；唯一不触发的是 @ 前为英文字母/数字/._%+-（像邮箱地址，避免打扰）。
- 全角 ＠（中文输入法常见）同样触发，插入时统一成半角 @；已保存文本里的 ＠名字 也能被解析和高亮、能汇总到人物详情。
- **事件表单也加上了 @ 选人**（所有者原话提到「添加事件时」）：首页日期详情里加/改事件，标题和备注打 @ 都能选人，事件标题里的提及也会高亮。
- 回归测试锁定：端到端改为「下午跟@张」（无空格）输入，必须弹出选人条并成功插入；事件备注同样有全流程用例。

## 2. 页面被放大、左边被切——已修复（根因明确）
所有者截图：首页整体被放大、左侧内容切出屏幕。
根因：全局输入框字号是 15px，低于 iOS Safari 的 16px 自动放大阈值——他在记录页点进故事框输入时 Safari 自动放大页面，回到首页也不还原，于是整页处于放大可横移状态。本地实测页面本身无横向溢出（390px 视口 scrollWidth 恰为 390），与该判断一致。
修复：.input 字号统一改 16px（人物页的无边框输入本来就是 16px）。端到端加断言：故事输入框计算字号必须为 16px。

## 3. 联系方式改自定义条目（所有者要求，参考苹果通讯录「添加个人社交资料」）
- 不再默认列出微信/抖音/Instagram/WhatsApp 等一排固定框。改为自由条目：一行 = 红色删除圆钮 + 蓝色名称输入 + 内容输入；底部有「＋ 添加一项（名称自己起）」和常用名称快捷片（手机/微信/QQ/邮箱/抖音/Instagram/WhatsApp/X/小红书，点一下加一行，也可完全自己起名，如「欧易」「学校地址」）。
- 数据：Person 新增可选字段 contacts[{label, value}]（Dexie 可选加键，不升版本）；旧固定字段（phone/wechat/…）打开编辑时自动折算成条目，保存后统一存进 contacts 并清掉旧字段——**已有数据一条不丢**，详情页与 Markdown 备份都按条目展示。
- 详情页智能动作保留：名称含手机/电话或内容像号码 → 可点拨打；内容像邮箱 → 可点写邮件。

## 4. 人物头像（所有者要求，像阅迹加封面：一眼认出是谁）
- 编辑页顶部居中头像：点「添加照片」从相册选，自动居中裁正方形、缩到 256px、压成 JPEG（约几十 KB）；可更换、可删除；没照片时显示名字首字圆圈（苹果通讯录同款兜底）。
- 列表每行左侧 40px 圆头像；详情页名字上方 92px 大头像。
- 存储：新增 Dexie v4 表 avatars（独立表，不动 people 记录形状；v3→v4 只加表，旧数据直接升级）。头像只存本机，**会进自己的备份导出**（导出新增可选 avatars 字段，校验和仅在有头像时纳入，旧备份文件照常验得过、恢复时没头像也不报错），绝不进 LIFEOS 交换文件。

## 5. 顺带的 UI 打磨（参考阅迹完成度）
- 底部导航加滑动指示块：切换首页/人物时选中块平滑滑过去（与生息/阅迹底栏的滑动指示同一思路，两 Tab 版简化为点按滑动）。
- 首页日期列表：完全没记录的日子改成安静的瘦行（无卡片底、降透明度），有内容的日子仍是卡片——列表不再被一排「无记录」空卡片淹没（所有者截图里正是这个问题）。

## 6. 数据与协议影响
- Dexie v3→v4（只加 avatars 表）；Person 加可选 contacts；lifeos-export-v1 加可选 avatars 字段（向后兼容，旧文件可导入、旧校验和可验过）；lifeos-exchange 交换协议零改动；自动分锚点、六维、导出其余口径零改动。
